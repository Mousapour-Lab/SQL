# Interview questions about this repository

20 questions an interviewer can ask about this project. Each one has a one-line hint, not an answer: work out the answer from the code before you use it.

## Schema and constraints

1. Why are `quantity_on_hand` and `reorder_point` separate columns instead of one "stock level"?
   *Hint: think about what a reorder point means and who sets it.*

2. What happens if you try to delete a supplier that has items and purchase orders?
   *Hint: the foreign keys have no `ON DELETE` clause — check what that implies.*

3. Why is `items.supplier_id` allowed to be NULL, while `purchase_orders.supplier_id` is not?
   *Hint: an item can exist before it has a supplier; an order cannot exist without one.*

4. What does `UNIQUE (po_id, item_id)` in `purchase_order_lines` prevent, and why does it matter when receiving?
   *Hint: two lines for the same item would create two movements for one item.*

5. Which constraint actually makes negative stock impossible, and which one only gives a nice message?
   *Hint: compare `ck_items_qty` with the check inside `issue_stock`.*

6. Why store `unit_price` on the order line when `items` already has `unit_price`?
   *Hint: prices change over time; the order must keep the price of the day.*

## Identity columns

7. What is the difference between `GENERATED BY DEFAULT` and `GENERATED ALWAYS` as identity?
   *Hint: the seed file inserts explicit ids — which variant would allow that?*

8. Why does `02_seed_data.sql` end with `ALTER TABLE ... START WITH LIMIT VALUE`?
   *Hint: do explicit inserts advance the sequence?*

## Triggers

9. Why is `trg_movements_ai` an `AFTER` trigger and not `BEFORE`?
   *Hint: if a later check fails, is the movement recorded?*

10. How does the stock trigger handle the two directions without two triggers?
    *Hint: `:NEW.movement_type` inside one `IF`.*

11. What is `:NEW` and what is `:OLD`, and where is each one available?
    *Hint: one exists on INSERT, both exist on UPDATE.*

12. `trg_items_biu` updates `updated_at` even when only the stock changes. Why?
    *Hint: the stock trigger writes to `items` too — which triggers fire then?*

13. Why is there no `WHEN OTHERS THEN NULL` in either trigger?
    *Hint: what would be stored if the error were hidden?*

14. Could you do the same stock update without a trigger? What would you lose?
    *Hint: think about inserts made outside the package.*

## Package and exceptions

15. Why put these procedures in a package instead of three standalone procedures?
    *Hint: spec vs body, shared exception, one compile unit.*

16. Why does the package never call `COMMIT`?
    *Hint: who should own the transaction?*

17. How does the caller catch `e_insufficient_stock`, and what makes that possible?
    *Hint: `PRAGMA EXCEPTION_INIT` binds a number to a name.*

18. Why is `-20001` used both in `PRAGMA EXCEPTION_INIT` and in `RAISE_APPLICATION_ERROR`?
    *Hint: the number is the identity of the exception.*

19. `issue_stock` uses `FOR UPDATE`. What problem does it solve, and what does it cost?
    *Hint: two sessions, same item, plus a lock until commit.*

## Views and transactions

20. In `v_po_summary`, why `COUNT(DISTINCT po.po_id)` instead of `COUNT(*)`?
    *Hint: the join repeats a PO header once per line.*

## Asking back

Two questions worth asking an interviewer about a real system:

- How is stock corrected when a physical count does not match `quantity_on_hand`?
- Are stock movements ever deleted or reversed, or only appended?
